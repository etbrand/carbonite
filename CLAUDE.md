# CLAUDE.md

## Project Overview
An R package providing Shiny input, output, and layout bindings for IBM's Carbon Design System (`@carbon/web-components` and `@carbon/styles`).
- **R Stack:** R, `shiny`, `htmltools`, `roxygen2`, `devtools`, `testthat`, `cli`
- **Frontend Stack:** Node.js, `@carbon/web-components`, `@carbon/styles`, Sass, custom `Shiny.InputBinding` / `Shiny.OutputBinding` JavaScript

## Common Commands
### Frontend (Node)
All npm commands run from `srcjs/` (that's where `package.json` lives), e.g. `cd srcjs && npm run build`.
- **Install JS dependencies:** `npm install`
- **Build JS/CSS bundle:** `npm run build` (outputs to `inst/www/carbon/`)
- **Watch mode for development:** `npm run watch`
- **Run JS tests:** `npm test` (Vitest + happy-dom; `npm run test:watch` to re-run on change)
- **Run single JS test file:** `npm test -- test/utils.test.js`

`npm test` goes through `srcjs/scripts/vitest.mjs` rather than calling `vitest` directly: on Windows a lower-case drive letter in the working directory (`c:\...`) makes Vitest fail with "Vitest failed to find the runner". Keep the wrapper.

### R Package
- **Update documentation & NAMESPACE:** `Rscript -e "devtools::document()"`
- **Run all tests:** `Rscript -e "devtools::test()"`
- **Run single test file:** `Rscript -e "testthat::test_file('tests/testthat/test-filename.R')"`
- **Run R CMD check:** `Rscript -e "devtools::check()"`
- **Install package locally:** `Rscript -e "devtools::install()"`

## Architecture & Directory Structure
- `R/` — R wrapper functions for Carbon components, `htmltools::htmlDependency()` definitions, and `update*()` server functions
- `inst/www/` — Compiled JavaScript bundles, Carbon CSS, and custom Shiny input/output bindings (generated by Node build; do not edit compiled files manually)
- `srcjs/` — Source JavaScript and Sass; entry point `srcjs/carbonite.js`, input bindings in `srcjs/bindings/`
- `srcjs/test/` — Vitest unit tests for the bindings. `test/setup.js` stubs the global `Shiny` object (use `getBinding("carbon.xxx")` to fetch a registered binding) and provides real jQuery. Carbon components are not loaded, so `cds-*` elements are plain elements whose properties tests set directly.
- `man/` — Auto-generated `.Rd` documentation files (generated via `devtools::document()`)
- `tests/testthat/` — Unit tests for R tag generation, attribute mapping, dependency attachment, and the messages sent by `update_carbon_*()` (`helper-inputs.R` provides a `fake_session()` that records them)
- `data-raw/` — Demo Shiny apps showcasing Carbon components and bindings (excluded from the package build)

## Code Style & Conventions
### R Conventions
- Prefix internal helper functions with a dot (e.g., `.build_carbon_tag()`).
- Use `cli::cli_abort()` for user-facing input validation and error messages.
- Document all exported functions with `roxygen2` tags (`@param`, `@return`, `@export`, `@examples`) and run `devtools::document()` after modifying signatures.
- Return `htmltools::tagList` or `htmltools::tags` objects with attached `htmlDependency()`. Every exported component attaches `carbon_dependency()` itself (via `.build_carbon_tag()` or `.with_carbon_dependency()`) so it works outside `carbon_page()`; htmltools de-duplicates it.
- Always namespace calls (`htmltools::tags$div`, not `tags$div`): the package must not rely on the user having attached `shiny`. Add any newly used package to `Imports` in `DESCRIPTION`.

### Carbon & Shiny Binding Conventions
- **Web Component Events:** Carbon Web Components emit custom events (e.g., `cds-number-input`, `cds-select-selected`, `cds-checkbox-changed`). Always listen to Carbon's custom events rather than standard native DOM `change` events. Exception: `cds-text-input` emits no custom input event, so its binding listens to the native `input` event (composed, bubbles out of the shadow root). Check the component source in `srcjs/node_modules/@carbon/web-components/es/components/` before assuming an event name.
- **Selected Values:** Shiny serialises length-1 R vectors as scalars, so a message's `value` may be `"a"` or `["a", "b"]`. Normalise with `toValueArray()` from `bindings/utils.js` and compare exact values, never `string.includes()`.
- **Shadow DOM Values:** Read component state from the host element's properties (e.g., `el.value`, `el.checked`, `el.selected`) rather than querying inside `#shadow-root` unless required.
- **Reactivity Propagation:** Ensure `subscribe(el, callback)` invokes `callback()` on the exact Carbon custom event so downstream Shiny `reactive()` expressions invalidate properly (not just `observeEvent()`).
- **Update Messages:** Handle `receiveMessage(el, data)` in custom input bindings to support R `update*()` functions, updating element properties/attributes cleanly without triggering infinite event loops.

## Workflow & Verification Rules
1. Whenever modifying files in `srcjs/`, run `npm test`, then `npm run build` so `inst/www/` reflects the latest bundle before running R tests.
2. Whenever adding or modifying exported R functions or parameters, run `devtools::document()`.
3. Never manually edit files inside `man/` or `NAMESPACE`.
4. Add `testthat` tests for every new component wrapper, verifying rendered HTML attributes, CSS classes, and dependency attachment.
5. Add Vitest tests in `srcjs/test/` for every new or changed input binding, covering `find`, `getValue`, `subscribe`/`unsubscribe` (the exact event), and `receiveMessage`.
6. Keep the R `update_carbon_*()` message keys and the JS `receiveMessage()` in sync: test the keys on the R side (`test-update-inputs.R`) and their handling on the JS side.
